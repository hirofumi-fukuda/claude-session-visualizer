# project-session — 採番セッションの起動と復元

マルチタスクで並行するセッションを「案件×採番」で管理するための型。
可視化ツール（`<VISUALIZER_DIR>`）が発話冒頭の採番合言葉を拾って
案件×セッション地図を作るので、**この型で始めたセッションだけが地図に番号付きで並ぶ**。

## A. 台帳（正本）の引き方

台帳は新規に作らない。**正本＝ワークスペースごとの auto-memory**。

| ワークスペース | 台帳ディレクトリ | 索引 |
|---|---|---|
| `<WS1のパス>` | `~/.claude/projects/<WS1のエンコード名>/memory/` | `MEMORY.md` |
| `<WS2のパス>`（あれば） | `~/.claude/projects/<WS2のエンコード名>/memory/` | `MEMORY.md` |

引き方: 索引 `MEMORY.md` の1行リストから案件に対応する `project_*.md` を選ぶ。
複数候補が出たら候補を提示して確認する（勝手に決めない）。該当が無ければ「新規案件」として扱い、
最初のセッション終了時に台帳（memory ファイル）を新規作成する。

## B. 起動フロー（「〈案件名〉 S〈n〉 開始」と言われたら）

1. **番号の確認** — 言われた n をそのまま使う。n を言われていない／「続き」なら:
   ```
   python <VISUALIZER_DIR>\session_no.py "<案件名>"
   ```
   が「〈案件名〉 S〈次番号〉 開始」を返すので、それを提示して確認を取る。
2. **台帳を読む** — A の手順で正本を特定して読む。見るのは 現在地・Next・ブロッカー・
   直近の意思決定・**📨申し送り（他セッションからの連絡。消化したら欄から消す）**。
3. **隣を1行だけ見る** — `python <VISUALIZER_DIR>\live_board.py` を1回実行し、
   **いま並行で動いている他チーム**（🟢/🟡/🔴）があれば要約に1行ずつ添える。休眠の羅列は不要。
   メモリは「終了時更新」なので他チームの *いま* はライブボードが正・台帳は *ここまで* が正。
4. **要約を返す**（このフローの成果物）:
   ```
   🗂️ 〈案件名〉 S〈n〉 開始   ※正本: <台帳ファイルのパス>
   📍 前回の最後の状況: …
   👥 並行チーム: 〈案件〉が🟢作業中 / なし
   ▶️ Now / Next / Blocked: …
   ```
   → 「今日はどこから？」を確認する。Next からおすすめは添えるが、**最終判断はユーザー**。
   復元しただけで勝手に着手しない。
5. 採番合言葉が冒頭発話にあれば jsonl 先頭に残る＝可視化ツールが自動で拾う。
   こちらから jsonl に書き込む必要はない（`~/.claude` は読み取り専用で扱う）。

## C. セッション終わり（記録）

「今日はここまで」「記録して」等で終了処理。
**MEMORY.md 冒頭へのセッションブロック積みは司令塔セッション専用**。
トラックセッションは案件の台帳側（`project_*.md`）だけ更新する:

- 現在地/ステータスを今日の結果で更新（Done を消し、新しい Next を入れる）
- 決めたことがあれば意思決定ログに1行追記（蒸し返し防止）
- 「S〈n〉: 〈成果・次の一手〉」の1行をセッション履歴に残す

追記は要点のみ。台帳を肥大させない。二重管理しない（新規ログファイルを作らない）。

### 台帳の標準セクション（新規台帳はこの型で・既存も順次揃える）

```markdown
## 現在地（最終更新: S〈n〉 / 日付）
## Next（推奨順）
## ブロッカー / ユーザー判断待ち
## 📨 申し送り（他セッションから。起動時に必読→消化したら消す）
## 意思決定ログ（1行×時系列・蒸し返し防止）
## セッション履歴（S〈n〉: 成果1行）
```

**書き先ルール3択**: ①自案件の話→自分の台帳（既定）②特定の他案件に伝えたい→
相手台帳の 📨申し送り 欄に直接書く ③全セッションが踏みうる地雷/規律→ MEMORY.md 昇格
（司令塔セッションの承認制。索引は全セッションのコンテキストに毎回載る＝全員がコストを払う）。

## D. セッション状況を見たいと言われたら

| 聞かれ方 | 返すもの |
|---|---|
| 「いまどれが動いてる？」「セッション状況」 | `python live_board.py`（ターミナル1回表示）の結果を要約 |
| 「ライブボード出して」 | `live_board.bat`（ブラウザ・10秒自動更新） |
| 「案件ごとの棚卸し」「地図」 | `claude_dashboard.bat` または `python l0_report.py` |
| 「あのセッション後で再開したい」 | `python live_board.py pin <sid接頭辞> [メモ]`（📌再開予定に載る） |
| 「他チームの現在地まとめて」「受付」「カウンター」 | `python counter.py`（回覧板＋全台帳の近況＋未消化📨） |

すべて `<VISUALIZER_DIR>` で実行する。
案件の分類が外れていたら、コードではなく `config.local.json` の `title_hints` /
`project_aliases` を足して直す（配列順＝優先度・先勝ち）。

## E. アンチパターン

- ❌ セッション専用ログを新設して二重管理 → 正本は auto-memory の台帳1枚に追記
- ❌ 復元せずいきなり作業 → 現在地/Next/意思決定を読んでから
- ❌ 着手案件・優先度の決め打ち → おすすめは出すが最終判断はユーザー
- ❌ 分類ズレをコード修正で直す → `config.local.json` を育てる
