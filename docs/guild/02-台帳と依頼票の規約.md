# 02 — 台帳と依頼票の規約

## 台帳 = auto-memory の project_*.md 1案件1枚

新規にログファイルを作らない。正本はワークスペースの auto-memory
（`~/.claude/projects/<エンコード済みWSパス>/memory/project_*.md`）。二重管理は禁止。

### 標準6セクション（新規台帳はこの型で・既存も順次揃える）

```markdown
## 現在地（最終更新: S〈n〉 / 日付）
## Next（推奨順）
## ブロッカー / ユーザー判断待ち
## 📨 申し送り（他セッションから。起動時に必読→消化したら消す）
## 意思決定ログ（1行×時系列・蒸し返し防止）
## セッション履歴（S〈n〉: 成果1行）
```

エージェントカウンターはこの型を前提に描画する（揃っていない台帳は先頭N行フォールバック）。

### 索引 MEMORY.md

台帳1枚につき1行のリンク＋要約フック。**全セッションのコンテキストに毎回載る＝全員がコストを払う**ので、
載せる内容は司令塔の承認制。台帳の中身を索引にコピーしない。

## 書き先ルール3択

1. 自案件の話 → 自分の台帳（既定）
2. 特定の他案件に伝えたい → **相手台帳の📨欄に直接書く**（WSをまたいでも同じ）
3. 全セッションが踏みうる地雷/規律 → MEMORY.md 昇格（司令塔承認制）

## 依頼票（宛先あり・消化で消える）

- 相手台帳の「📨 申し送り」欄に書く。書式: `**【依頼票】タイトル（発注元 S〈n〉 から 日付）**: 本文`
- 受けた側はセッション起動時に必読 → **消化したら自分で消す**（完了報告が要るなら発注元台帳へ返信の依頼票）
- 消し忘れは司令塔の定例（発注消化チェック）が検知する。司令塔が消化を実測確認して消し込み代行することもある

## 回覧板（宛先なし・読めば終わり）

メモリディレクトリに `BULLETIN.md` を1枚。**書くのも下げるのも司令塔だけ**。既読管理はしない。
「全員が踏みうる規律・全体に効く決定」だけを貼る。表示はカウンターの先頭（CLI/HTML両方）。

```markdown
---
name: bulletin
description: 回覧板 — 宛先なし・読めば終わりの全体周知。書くのも下げるのも司令塔
metadata:
  type: bulletin
---
# 📋 回覧板
（説明文）
## 掲示
（なし）   ← 貼るときはここに。下げるときは「（なし）」に戻す
```

## 採番運用

- 開始合言葉「**〈案件名〉 S〈n〉 開始**」を発話の冒頭に書く（可視化ツールが jsonl 先頭から拾う）
- 次番号は `python session_no.py "<案件名>"` が即答する
- セッション終了時: 台帳の現在地/Next を更新・決定を1行追記・「S〈n〉: 成果1行」を履歴に残す
- 案件の分類がズレたらコードでなく `config.local.json`（title_hints / project_aliases）を育てる

## 司令塔定例の型

- **軽量版（作業日の頭・5〜10分）**: ①発注消化チェック（出した依頼票は消化されたか＝実物で裏取り）
  ②滞留チェック（委託ジョブの生死・日次自動処理のログ・意図的保留は対象外）③自分宛の依頼票消化。
  判断は各台帳の📨へ発注として書く。実作業はしない
- **フル定例（滞留が溜まったら宣言実施）**: 軽量版＋全台帳の棚卸し・用語の🌱仮置き審査・
  優先度Top改訂・（あれば）白書レビュー・索引の整理
- 定例の最後に司令塔だけが MEMORY.md 先頭へセッションブロックを積む（トラックは台帳のみ更新）
