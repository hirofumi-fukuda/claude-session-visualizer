# 04 — ギルドとワークスペース運用（workspaces.json ガイド）

> 作成: 2026-08-10（会社S15・claude-wt 導入と同時に確定）
> 関連: [01-ギルドの仕組み](01-ギルドの仕組み.md)（5階層・3役割）／`claude-wt/README.md`（ランチャー操作）

## 等式の正体: ギルド ＝ ワークスペース ＝ claude プロジェクト

この等式は**機械的に保証されるものではなく、規約で保っている**。

- **機械側**: claude は「起動時の cwd」単位で `~/.claude/projects/<cwdのスラッグ>/` を自動生成し、
  そこに履歴（jsonl）・メモリ（memory/MEMORY.md）を置く。claude は「ギルド」を知らない。
- **運用側**: ギルド＝人間が決めた作業単位。**「ギルドのルートでしか claude を起動しない」**
  という規約を守る限り、ギルドと project ディレクトリが1:1で一致し、採番・メモリ・
  ライブボードの地図がすべて同じ入り口に揃う。
- **規約の強制装置**: Cursor の .code-workspace／claude-wt の ➕新規ボタン・launch.ps1。
  どちらも「ルート以外で焚けない」導線にすることで等式を守る。

⚠️ ギルド外の cwd で起動すると「**はぐれ project**」が勝手に生える（採番・メモリが届かない
場所にセッションが落ちる）。2026-08-10 時点の実測で、はぐれは Z--FBiz(6本)・
C--source-git-h-fukuda1207-FBiz(7本) など5フォルダ存在。ボードでは ws 別枠に見えるので
気づいたらギルドルートで焚き直す。

## workspaces.json（ギルド定義の正本）

- 場所: `claude-wt/workspaces.json`（**gitignore対象＝個人設定**。雛形は `workspaces.example.json`）
- 1エントリ＝1ギルド（`name` / `path`=ルート / `color`=タブ色 / `add_dirs`=通常空）
- ここが**唯一の定義点**で、以下すべてが自動追従する（再起動・再登録不要）:
  - ライブボード上部の **➕新規WTタブ** ボタン列（watcher が毎tick読み直す）
  - プロトコルハンドラ `claude-wt://new/<ギルド名>` の**検証ホワイトリスト**
    （URL にはギルド名しか載らない＝パスは常にこのファイルから解決・注入面なし）
  - `launch.ps1`（全ギルドのタブ束ね起動／`-Continue` で各ギルド最新セッション一括復帰）

## ギルドを増やす手順（3ステップ）

1. `workspaces.json` に1行追加（name/path/color）→ ボタン・検証・launch が自動追従
2. ルートに `.claude\CLAUDE.md` を置く（そのギルドの共通指示。無くても動くが素の claude になる）
3. 初回セッションで**採番・台帳の置き場**を決める（メモリ方式 or リポ内台帳方式）＋
   project-session スキルの A表に登録（これまで通り）

## claude-wt 操作の対応表

| やりたいこと | 操作 | 仕組み |
|---|---|---|
| 新しいセッションをギルド指定で焚く | ボードの ➕ボタン | `claude-wt://new/<ギルド名>` |
| 休眠セッションを続きから | ボードの ▶ 開く | `claude-wt://resume/<uuid>`（cwd は jsonl から逆引き） |
| resume コマンドだけ欲しい | ボードの 📋 | クリップボードへコピー |
| 前回の稼働タブ一式を復元 | `restore_tabs.ps1` | watcher が毎tick保存する `reports/tabs_snapshot.json` から |
| 各ギルドの最新セッションで朝を始める | `launch.ps1 -Continue` | ギルドごとに `claude -c` |
