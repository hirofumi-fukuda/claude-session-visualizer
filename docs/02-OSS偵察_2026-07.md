## 2. 照準別の推奨（既存 vs 自作）

### 照準① 案件×セッション地図 → 自作（ただしパース層は参考にする）
- 「冒頭メッセージの採番規約→案件マッピング」を持つツールは**皆無**。既存のグルーピング軸は全て cwd フォルダか git ブランチ。
- 同一cwd（OneDrive業務ハブ）で多数案件が混在する運用は cwd グルーピングでは原理的に解けない。ここが自作の核。
- 発展形: 検出した採番を SDK の `tag_session()` / `rename_session()` で**セッション本体に書き戻す**と、公式 `/resume` ピッカーや既存ビューアでも案件名が見える。

### 照準② 並行セッションの今 → 既存を使う
- まず**公式 Agent View（`claude agents`）**。ブラウザ俯瞰なら **claude-view**。自作は再発明なのでやらない。

### 照準③ エージェントの中身 → 既存を使う
- **claude-view のサブエージェントツリー**が要求そのもの。静的Markdown化なら **claude-code-log**。

### 照準④ 利用統計 → 既存を使う
- **ccusage**。「案件別トークン集計」だけ照準①の自作に相乗り。

### 総合戦略
フルスクラッチ4機能は過剰。**自作は照準①のマッピングエンジン（＋案件別集計）に絞り**、②③④は claude-view / Agent View / ccusage を当てるのが最小構成。

## 3. 仮説検証: 「照準①は既存に無い独自価値」→ 正しい（確度高）

- 15本超の調査で採番規約マッピング機能を持つツールはゼロ。
- 傍証: 公式リポジトリに「セッションのタグ/案件別整理が欲しい」feature request 複数（[#22617](https://github.com/anthropics/claude-code/issues/22617), [#50031](https://github.com/anthropics/claude-code/issues/50031), [#36968](https://github.com/anthropics/claude-code/issues/36968)）＝未充足ニーズ。
- ただし公式が「タグ付けの器」（custom title・`tag_session`）を用意し始めている。独自価値は「**採番規約を自動検出して器に流し込む/地図に描く**」部分に収斂。
